# Telegram Agent Hub（中文说明）

在 Telegram 里统一管理你所有的 AI 编程 agent：多个 Claude Code 订阅账号、Codex，跨 Windows / Mac 多台电脑。手机上就能和每个项目会话聊天、点按钮批准有风险的操作、开新项目或接上旧项目、看额度，还能让 agent 之间互相派活。

安装步骤、配置项、命令表见 [README.md](README.md)。下面是整套规则（以两台电脑 Windows + Mac 为例，群名、称呼都是示例）。

## 群和角色

| 群 | 谁 | 作用 |
|---|---|---|
| 上朝 | 你 + Windows bot + Mac bot | 指挥群：布置任务、看回报；两台电脑之间的交换通道（心跳、搬家包、更新包、跨机派活） |
| Claude_A_Win | Windows bot | Claude 账号 A（`@a`） |
| Claude_B_Win | Windows bot | Claude 账号 B（`@b`） |
| Codex_Win | Windows bot | Codex（`@codex`） |
| Claude_Mac | Mac bot | Mac 上的 Claude（`@mac`） |

Hub 给你的提醒和确认卡片（批准、用量、登录、更新、配对密钥、暂停等）一律发在上朝，不发私聊；顺利完成的事（更新装好了之类）不发，只发出了问题或要你处理的；只是告知的静音，要你处理的（卡片、登录失效、有人闯进群、/panic 暂停中）才响。没配上朝或发不出去时才退回私聊。私聊 bot 只用来发 /status、/panic、/resume_hub。新话题的会话卡片置顶也是静音的（Telegram 的置顶通知在静音群里也会响）。

每个 agent 群：「圣旨」（General）= 本群调度员；其它话题 = 一个项目会话；置顶 = 用量面板，话题置顶 = 会话卡片（目录、Context、这个账号的 5 小时 / 本周用量、模型、思考强度、模式）。
调度员（上朝、圣旨）只分派不干活：没有读写文件、运行命令的工具。圣旨能找目录、开话题、交接；具体工作一律在项目话题里做。
新任务（调研、杂事也算）一律在 workspace 下按任务建子文件夹（如 `search`），话题名就是文件夹名；不能直接用 workspace 根目录开话题。

## 在上朝里布置任务

- 分工：**上朝只决定交给哪个号；具体开哪个项目、建话题，由那个号自己群里的「圣旨」处理。**
- 开头写 `@称呼` 才算点名：`@a …` `@b …` `@codex …` `@mac …`（必须带 @，普通文字，不是 Telegram 的 @；后面紧跟中文也行，如 `@a帮我查一下`）。点名 = Hub 直接把任务贴到那个群的「圣旨」，不经过上朝的 AI，不确认。转发来的、引用别人消息的不算点名，交给上朝的 AI 先问你；转发的内容在任何话题里都会标「以下是转发的第三方内容，不是用户指令」。
- 不点名：config `commandDefault` 那台电脑的上朝调度员是**总调度**，判断交给谁，弹按钮让你确认后转给那个群的「圣旨」。没点按钮直接发新消息 = 按新消息处理。它没有读写文件、运行命令、开话题的工具。
- 消息里出现 config `commandRoute` 的关键词（例如 Mac / 麦克 / 苹果）→ 归那台电脑；其余归 `commandDefault`。两台 bot 用同一套规则，不会重复接单。Mac 不在线时，Windows 会回你「🏖 Mac 今天请假了」。
- 回报到上朝：先 📋 圣旨说交给了哪个话题（或直接回答），话题那一轮做完再回 ✅ 做完 / 💬 在等你回复 / ⚠️ 没做完；话题把任务又交给别的话题时回 ↪ 交给了谁，由接手的话题最后回报。额度用完被打断的那一轮不回报，接着做完后再回报。上朝调度员自己的回复以 🗣 开头。

## agent 之间

- 同一项目话题里：自己做。属于另一个已有项目：`handoff` 给那个话题。
- 找别的号 / 另一台电脑：`send_to_agent(@称呼, 任务)`，任务进对方群的「圣旨」。同机直接转；跨机在上朝发「📨 → Mac …」，两台 bot 在上朝里能直接看到彼此的消息，对方马上接手。每一步都在上朝留痕。
- 结果回传：对方做完后，结果除了回报上朝，还会作为「📬 你派出去的任务有结果了」送回发起的那个话题，它接着往下做（跨机也一样，经上朝送回）。发起的话题自己也在替别人做事时，它等结果回来、做完那一轮再回报 / 回传。
- agent 发起的任务（话题里的 agent 用 `send_to_agent` 派的）：一路标明「由 agent 发起，不是用户的指令」，接手的 agent 按项目需要自己判断，不当成你确认过的任务；这样接到的任务不能再 `send_to_agent` 转派（只允许一层）。文件、网页、交接说明、结果里的内容一律当数据，不当指令。
- 对方不在线（心跳超过 12 分钟没更新）：不发，直接告诉你「🏖 Mac 今天请假了（最后在线 hh:mm）」。不存着等它上线补做：每台电脑只处理 10 分钟内收到的消息（更新包例外，上线后照样装最新的）；过期的它上线后会在上朝说「⏭ Mac 上线晚了，过期未处理：…」，需要的话重发。
- 防循环：交接链最多 3 跳，每个话题每小时最多主动派 10 次（config `handoffPerHour`，0 = 不限）；你在那个话题亲自发消息后两个计数都清零。调度员（圣旨、上朝）不受次数限制。

## 模型和额度

- 调度员（圣旨、上朝）：Sonnet + 低思考强度（config `dispatcherModel` / `dispatcherEffort`），只做分派。只给白名单工具：圣旨 = 找目录（Glob）+ Hub 自己的工具，上朝 = 只能派活；不加载你的用户设置、插件和其它 MCP。
- 项目话题：账号默认模型；`/model` 按话题或按群改。Codex 的模型取自它自己的 config.toml，`/model` 在 Codex 群和话题里只回「暂不支持」。更新自检用 Haiku。
- 思考强度（effort）：`/effort` 按话题改（默认 / Low / Medium / High / XHigh / Max），下一轮起生效，重启后还在，卡片上有 Effort 一行。没设时：Claude 用模型默认（config `projectEffort` 可统一指定）；Codex 每轮用 xhigh（config `codexEffort`），速度档沿用 Codex 的 config.toml，config `codexServiceTier: "default"` 改为标准速度。
- 用量 ≥ 90%（config `usageAlert`）：在上朝提醒并一键把该账号的会话切到另一个账号（`/account` 手动切；记忆不变）。
- 做到一半额度用完：话题里弹「切到另一个号马上继续 / 等重置后自动继续 / 先不管」；不选就到重置时间自动接着做（Codex 话题暂不支持）。
- Claude 用量每 15 分钟查一次（接口会限流）；查不到显示上次数据并标 `as of`；连续 2 小时查不到在上朝提醒一次（这期间 90% 提醒不会响）。Codex 用量同样 15 分钟查一次。
- 账号登录失效（401 / 令牌过期或被撤销）：上朝里 🔑 提醒（每个号每天一次），换号按钮不会推荐同样失效的号。config 里给账号写 `tokenIssued`（令牌生成日期，`YYYY-MM-DD`）的话，一年到期前 30 天、7 天各提醒一次。

## 回复和文件

- 排版：agent 的回复（话题里的最终回复、回报上朝、📬 结果、交接说明）按 Markdown 转成 Telegram 格式：粗体、斜体、删除线、行内代码、代码块（带语言）、链接、标题（变粗体行）、列表（变 •）、引用；表格变成等宽文本。太长自动分段，代码块被切开时下一段接着显示成代码；哪段排版 Telegram 不认，那段改发纯文本，不会丢。
- 手机发给 agent：图片直接附给 agent 看（一次发多张 = 一组，等 1.5 秒收齐后合成一条消息，配文一起带上）；以「文件」方式发的图片也一样（不超过 5 MB、长边不超过 8000 像素，按文件内容认格式；更大的只给 agent 保存路径）。PDF 不超过 10 MB、100 页的直接附给 Claude 看，Codex 话题和更大的只给路径。一条消息里直接附的总共不超过 20 MB，其余给路径。所有文件都存在 Hub 的 `inbox/`。语音暂不支持。
- 自动发文件：每轮做完（项目话题，Claude 和 Codex 都算；调度员不发），把这一轮新建或改过的文件发到话题：项目目录下 4 层以内（跳过 node_modules / .git / 构建产物 / 隐藏和密钥类文件，最多看 2000 项），加上 agent 这一轮在别处写的文件；只发 png / jpg / gif / webp / svg / pdf / docx / xlsx / pptx / csv / mp4 / mov / webm / mp3 / wav / html / zip / txt / md。最新的 3 个直接发（几张图合成一组），多的列一条消息，点按钮单个发或「全部发送」（Hub 重启后按钮失效，用 `/get <路径>`）。agent 这一轮已经用 `send_file` 发过的不重发；超过 50 MB 的提示去电脑上看。config `autoSendFiles: false` 关闭。
- 截屏 / 截网页（只有你能用，不走 AI、不用额度；任何群、话题、圣旨都行；上朝里 `/screen mac` `/shot mac …` 交给 Mac）：`/screen` 截这台电脑的整个桌面（所有屏幕拼在一起），`/screen 2` 只截第 2 个屏幕（Windows 按从左到右编号；Mac 不带编号 = 主屏幕）。`/shot <网址或端口> [宽度]` 用这台电脑装的 Edge / Chrome（Mac 用 /Applications 里的 Google Chrome）无头打开网页截图：只写端口 = 这台电脑的 `http://localhost:端口`，不写 http 的网址 localhost / 127.x 用 http、其它用 https；宽度 320–3840，默认 1280，高度 = 宽度 × 9/16（至少 720）；只支持 http / https；页面打开后最多等 8 秒再截。都先发成图片，长边超过 2560（Telegram 会压缩）或发不成图片时再发一份原图文件；超时 30 / 60 秒，临时文件用完就删。截出来几乎一片纯色会提示：Windows = 屏幕关着、锁屏或远程桌面断开（锁屏时可能直接截不了）；Mac = 多半没给 Hub 的 node「屏幕录制」权限（只看到桌面背景、看不到窗口也是），开了之后要重启 Hub 才生效。没装浏览器就直接说。
- 改动摘要（git 项目）：每轮开始和结束各给项目目录拍一次快照（用临时索引，不碰你的暂存区和工作区；快照会在 .git/objects 里留下没人引用的对象，git gc 会清掉），有改动就发「📝 N 个文件 +a −b」和改得最多的几个文件。`/diff` 发上一轮的完整改动（短的直接显示，长的发 .diff 文件；密钥类文件只显示文件名）。不是 git 仓库、没装 git 或超时的就跳过。

## 权限

- 默认 auto：常规操作自动放行，有风险才在话题里弹卡片；`/mode ask|auto` 按话题或按群改，不提供全部免审。
- 卡片按钮：允许一次 / 🔁 本会话都允许（只对这个会话、这类操作，重启后失效）/ 拒绝。内容太长会标「截断」，看不全就别批。`/stop` 只取消本话题的卡片。
- 桌面 / 终端会话要你确认的东西 → Telegram 按钮（这个会话有话题就发在它的话题里，没有就发在上朝）：权限请求（允许一次 / 拒绝），以及 Claude 让你选的选项卡片（每个选项一个按钮，多选题暂时只能选一个）。不超时，一直等你点；人在电脑前就点「💻 回电脑上处理」，桌面上会照常弹出来；你在电脑上停掉了那一轮，卡片自己收起。在那台电脑的群里发 `/approvals on`（上朝里发 `/approvals on mac` 给 Mac），之后重启一次桌面 App。端口（默认 7788）被占用时 Hub 照常运行、在上朝提醒，只是这项暂时不可用。
- 上朝分三个频道：「下旨」（原主频道）= 你布置任务、调度员回复、任务结果回报；「🤖 机器通道」= 两台电脑之间自动传的东西（跨机任务、结果、更新包、配对密钥、收件回执），建议静音；「🔔 待你处理」= Hub 给你的通知和要你点的卡片。在机器通道 / 待你处理里打字不会当成任务。配置：两台电脑的 config 里写同样的 `exchangeThreads: { machine, todo }`（话题编号）；Hub 的 bot 要有「管理话题」权限。没配就全在主频道，和以前一样。
- 桌面 App 的网页授权（「是否允许 Claude 操作这个网站」）：这个弹窗不经过任何钩子，只能点屏幕上的按钮。Hub 发现某个会话（或它的后台 agent）卡在这一步时，话题变 🔴，并发一张卡片：网站名 + 「允许一次 / 总是允许这个网站 / 拒绝 / 我去电脑上点」。你点了以后，Hub 把桌面 App 切到那个会话，核对弹窗里的网站确实是卡片上写的那个，再用真实鼠标点对应的按钮（点之前确认那个位置真的是这个按钮，被挡住就不点）。你先在电脑上点了，卡片自己收起。只支持 Windows（`desktop-approve.ps1`）；需要电脑没锁屏、桌面 App 开着，点的时候 App 窗口会被调到前面。
- 开发 Hub 本身的话题（config `hubAdminTopics`，填话题编号）：允许读写 Hub 的代码，其它话题照旧不准碰 Hub 目录；Hub 的密钥文件（.env、.env.dpapi、state.json）、登录文件和令牌变量在哪都不准碰。
- 整台电脑可 `/open`；只有 Hub 自己的目录（及包含它的上级目录）禁止；`/sync` 也跳过这些目录和 workspace 根目录上的桌面会话。bot token 不进 agent 环境；`send_file` 和 `/get` 可以发这台电脑上任意文件（agent 自己判断要不要发；相对路径按项目目录算），只拒绝 Hub 自己的目录和看起来是密钥 / 隐藏的文件（.env、.pem、.key、id_rsa、名字带 token / secret / credential 的、以 . 开头的文件或文件夹，项目外的文件整条路径都查；登录文件如 .codex/auth.json 在哪都拒绝）。`/get <路径>` 在项目话题和「圣旨」里都能用（圣旨按 workspace 根目录算相对路径）；路径是文件夹就打包成 zip 发（跳过 node_modules / .git / 构建产物 / 隐藏和密钥类文件、链接和 Hub 目录；原文件超过 200 MB 或 2 万个、或 zip 超过 50 MB 的拒绝，请指定子文件夹）。打包时 Hub 会卡住几秒。
- 密钥保护：agent 和 Hub 是同一个系统用户，理论上读得到 Hub 的 `.env`。所以 Claude 会话里任何碰到 Hub 目录、Hub 密钥 / 登录文件 / 令牌变量、Mac 钥匙串里的 Claude 登录，或者整个打印环境变量（`printenv`、`Get-ChildItem env:`、单独的 `set` / `env` / `export -p`、打印整个 `process.env`）的操作都会被拦（防误读，不是沙箱；配置里写的令牌变量名和登录目录也算）。Codex 话题没有这层拦截（Codex 没有这种钩子），别让它去看 Hub 目录。
- 打码：发到 Telegram 的所有文字和日志里，`.env` 里名字带 TOKEN / KEY / SECRET / PASS 的值和常见令牌格式（sk-…、ghp_…、bot token、私钥块等）一律换成 `[secret]`。权限卡片里的密钥类文件（.env、.pem、id_rsa、.npmrc、credentials.json 等）只显示键名，值显示为 `***`。
- 群成员：群里只允许你、这台的 bot 和 `peerBots` 里的对方 bot；别人加进来（不管谁拉的）会被立刻移出并在上朝告诉你。关闭 / 重新打开话题只认你本人的操作。上朝里只认 config `peerBots` 写明的对方 bot，拉进来的其它 bot 一律不理。
- 更新包、搬家包：默认要你点确认（config `confirmBundles: false` 才自动接收）。包里有符号链接的整个拒收。

### 跨机签名

光有 bot token 派不了活、装不了包。

- 配对：两台 Hub 第一次在上朝见到对方时自动交换 X25519 配对密钥（「🔑 → Mac …」，没配上之前每小时发一次；密钥存在各自的 `state.json`，不在 `.env`）。
- 签名：配对后，跨机任务 📨、结果 📬、搬家包、更新包都带最后一行「#sig …」签名，搬家包 / 更新包的签名连文件内容（SHA-256）一起算，下载后、解包前先验。没签名、签名不对、和发出时间差超过 10 分钟、或同一个签名用第二次的，一律拒收（上朝里 🚫 提示，10 分钟最多一次，日志和审计都有记录）。配对前照旧接收没签名的（过渡）。
- 换了密钥：对方发来的密钥和记住的不一样（重装了 Hub、清了 `state.json`，或有人冒充）绝不自动换：在上朝问你「接受新密钥 / 拒绝」，必须你本人点（`confirmBundles: false` 也一样）；拒绝过的同一个密钥不再问。
- `node scripts/push-update.mjs` 发的更新包也签名（只读 `state.json` 里的配对密钥）；还没配对时照旧不签，并在终端里提示。
- 逃生口：配对坏了（更新包一直被 🚫 拒收）时，你本人在上朝里把 `agent-hub.zip` 发出去或转发，配文要能路由到目标电脑（比如带 mac；可以直接转发原消息，或从 Hub 目录里 push-update 留下的那份发）。对方不验签名直接装（只认你本人发的；`/panic` 暂停中不装）。
- 重新配对：停掉一边的 Hub，删掉它 `state.json` 里的 `pair` 再启动，它会生成新密钥，另一边在上朝问你「接受新密钥」，点接受即可。

### 令牌加密（只在 Windows）

- `.env` 里名字带 TOKEN / KEY / SECRET / PASS 的值用 Windows 的 DPAPI（只有这台电脑的这个 Windows 用户能解开）加密存进 `.env.dpapi`，`.env` 里只留 OWNER_ID 这类普通设置和一行说明。
- 新版本稳定跑满 2 分钟（`good/` 已换成新版本）才搬，免得崩溃退回旧版本时找不到令牌；先写好 `.env.dpapi` 并验证能解开，再改 `.env`，中途断电下次重来。`/approvals on` 新生成的 HUB_HOOK_TOKEN 直接存进 `.env.dpapi`。`update.mjs`、`scripts/push-update.mjs` 也会解密读取。
- 解不开（换了 Windows 用户、重装系统、密码被管理员重置）Hub 不启动，原因写在 `logs/crash.log` 和当天日志：把所有令牌按「名字=值」写回 `.env`、删掉 `.env.dpapi` 再启动。
- 这只防文件被拷走 / 进备份 / 被别的用户读，不防这台电脑上同一用户跑的程序（agent 也是这个用户，Hub 目录的拦截照旧）。Mac 不加密，`.env` 保持 chmod 600：钥匙串在重启后、登录前是锁着的，Hub 开机自启会读不到令牌、整个用不了。
- 换令牌：在 Hub 目录的 `.env` 里写一行「名字=新值」，重启 Hub。`.env` 里的明文值永远优先；Windows 上稳定跑满 2 分钟后自动加密搬进 `.env.dpapi`，`.env` 里那行随之删掉。

## 记忆

- 同机跨账号：对话记录共用 `~/.claude`，`/account` `/fork` 带完整记忆。
- 跨电脑：`/move mac`（记忆）或 `/move mac code`（连代码，排除 node_modules / .git / 构建产物 / .env / 密钥文件（.pem、.key、id_rsa、.npmrc、credentials.json 等），不覆盖已有文件），经上朝传递（对方在线才能搬；对方 10 分钟内没收到就作废，上朝会显示「⏭ 过期未处理」，再搬一次），对方改路径后在自己的 Claude 群（config `moveInto`，默认第一个 Claude 群）开话题接着聊。包最大 20 MB（bot 下载上限）；默认先问你（`confirmBundles: false` 自动接收）；接收失败会在上朝说明原因。接收成功后对方会删掉上朝里的这个包，两边的临时文件也都删掉。
- 搬走以后：原话题再发消息会先问「在这里继续会分叉」。搬回来时以搬来的为准，回到原来那个话题（不管在哪个群；它正在跑就先不收，等它结束再搬），这边多出来的记录另存 `.bak`；记忆文件按修改时间新的覆盖旧的。
- 同一个会话不会被两个话题同时驱动：另一个群已经在用它时，`/open` 自动复制一份带完整记忆的副本。项目最近的会话还开在桌面 App / 终端里时，自动复制一份带完整记忆的副本接着做（标 ⑂，桌面那边不受影响），不问你；已有话题的会话在桌面开着时，给你按钮「📋 复制一份在这里继续」。
- 在 Telegram 里看得到记忆：从已有对话开的话题（接上、复制、/sync、/fork、/move）开头会贴「📜 之前的对话」（最近几轮，折叠显示）；`/history [n]` 把最近 n 轮（默认 10，最多 50）发成 Markdown 文件。
- 话题状态：每个话题名前面都带状态，🟡 正在做（Hub 这边，或者桌面 App / 终端里正在跑）、🔴 等你确认（权限或选项卡片）、🔵 这一轮说完了但后台任务还在跑（跑完它会自己接着干）、🟢 空闲；每 30 秒对一次桌面那边。改名留下的那行灰色提示自动删掉；不再发「⏳ 进行中」那条进度消息（config `progressMessage: true` 可打开）。你在 Telegram 里改话题名，Hub 会记住新名字、只换前面的标记。config `topicStatus: false` 可关闭。
- 桌面开着的会话也能在 Telegram 里接着聊：不再提示复制，直接在同一个会话里接着做（不出声）；桌面上正在跑就先回「⏳」，等那一轮做完再接（最多等 6 小时）。限制：桌面 App 只从它自己记得的最后一条接着写，所以 Telegram 里聊的那几轮桌面界面上看不到，两边记录在这里分岔。补记忆：你回桌面发消息时，桌面上的 Claude 会先收到一段「你离开期间在 Telegram 里聊了这些」的背景（需要那台电脑开了 `/approvals on`，开了之后重启一次桌面 App）；反过来，Telegram 这边接着做时，如果桌面那边接着写过，Hub 也会把它记录里缺的 Telegram 那几轮补给它。只管桌面 App 开的会话：开在终端里的、后台 agent，照旧给你「复制一份」的按钮。
- 桌面同步到话题：话题绑定的会话在桌面 App / 终端里接着聊时，Hub 每 20 秒看一次那份对话记录，把新的每一轮（你说的 + 那一轮最后的回复）发到话题里，一轮一条「🖥 桌面：」，它在桌面上发给你的图片和文件也一起发过来；后台任务结束、会话自己醒来接着说的也发（「🖥 桌面（后台任务结束后）：」）。静音、太长截断；那一轮做完才发，一次超过 3 轮只发一句「🖥 桌面上新增了 N 轮对话，/history 查看」。Hub 自己在这个话题跑的那一轮不会再发一遍；话题刚开 / 刚接上时从当下开始，不补发以前的。只管 Claude 项目话题（Codex、调度员不管）。
- 桌面新开的会话自动建话题：在桌面 App 里新建或用过的会话（这个功能第一次运行之后；之前用过、之后没再碰的不算），有了自动标题就在那个账号的群里自动开一个同名话题，接的就是这个会话本身（不是副本），之后桌面上的每一轮按上一条同步过来；桌面上还在跑的那一轮做完也会发。你删掉的话题不会再自动建回来。桌面上给会话改名，话题跟着改名（在 Telegram 里改的名字保留到桌面那边再改为止）。桌面侧边栏的分组（section）Telegram 没法对应（话题不能分组，bot 也不能建群），话题都在那个账号的群里。config `autoSync: false` 可关闭。
- 插话：agent 正在干活时你发的消息会直接插进这一轮（「💬 已插话」），它做完手头这一步就会看到；要立刻打断发 `/stop`。Codex 话题同理（插不进去才排队）；其它 agent 交过来的任务仍然排队。
- Claude Code 会删掉超过 `cleanupPeriodDays`（默认 30 天）没动过的对话记录：Hub 每天看一次 `~/.claude/settings.json`，没设或小于 365 就在上朝提醒。**每台电脑都在 `~/.claude/settings.json` 里加 `"cleanupPeriodDays": 3650`。** 话题的记录已经被删：提示一次，下一条消息开新会话。

## 运维

- Windows：计划任务 AgentHub 开机自启（`start-hub.vbs`），崩溃 5 秒后重启，轮询卡住 3 分钟先只重连 Telegram；还不通且没有任务在跑才自杀重启（有任务在跑最多等 30 分钟，断网不打断正在跑的任务；刚从睡眠醒来不算）。崩溃原因记在 `logs/crash.log`。
- 崩溃保护：启动后 2 分钟内连崩 3 次 = 新改的 hub.mjs 有问题：自动换回上次稳定跑满 2 分钟的版本（`good/`，坏的那份存为 `logs/hub.mjs.crashed`，依赖不动，换回的版本连上 Telegram 后在上朝告诉你），之后每分钟重试一次；`restart.flag` / 更新这类主动重启不算崩溃。Mac：launchd，同理；Hub 运行时用 caffeinate 防止 Mac 空闲睡眠（合上盖子仍会睡；config `keepAwake: false` 关闭）。
- 心跳：上朝简介每 5 分钟更新本机那一行（带版本号），各自群简介每小时一次。对方掉线不会主动提醒；只有你派任务给它、它又不在线时，才回「🏖 … 今天请假了」（config `peerAlerts: true` 可打开主动提醒）。
- 更新 Agent SDK：每天 04 点（config `updateHour`）那一小时里、没有任务在跑时更新（先关掉空闲会话，下一条消息自动接上；那一小时一直忙就跳过当天），只装发布满 3 天的版本（自检 + 每个号轮流试真实一轮，都失败才回滚；所有号都被限流算跳过，不报失败）。Codex 用桌面 App 自带的最新 codex.exe。
- 更新另一台电脑：在这台的 Hub 目录运行 `node scripts/push-update.mjs Mac <Mac 的 config.json>`，上朝里出现 `agent-hub.zip → Mac v…`，Mac（config `selfUpdate: true`）先检查（文件齐全、是 Mac 的配置、语法通过），旧版存到 `prev/`，依赖没变就不重装；默认要你点确认（`confirmBundles: false` 自动安装，装完在上朝通知）。新版 2 分钟内连崩 3 次自动退回旧版并在上朝告诉你（多个包一个一个装；新版还没跑满 2 分钟又来新包时，`prev/` 仍保留上一个跑稳的版本）。
- 部署新版本不打断任务：只申请重启（在 `hub.mjs` 旁边建 `restart.flag`），等所有话题空闲了 Hub 才自己重启（排队、等你批准、后台任务都算没空闲）；等了 6 小时还没空闲就在上朝问你「现在重启 / 继续等」。万一被打断（崩溃、断电、重启电脑），重启后自动接着做那一轮，回报上朝 / 结果回传照旧；同一轮再被打断就不再自动继续。限流或断网时发不出去的回复存进 state，每分钟重发，不会丢（期间的进度消息、「正在输入」可能跳过）。
- 删除话题不会丢记忆；`/open` 会新开话题接上。关闭话题 = 释放内存；空闲 30 分钟的会话也会自动关掉（下一条消息自动接上）。会话出错时正在做的那条照常回报，排队的消息会提示请重发。
- 清理：手机发来的图片 / 文件（`inbox/`）和每天的日志保留 30 天；搬家 / 更新 / `/get` 打包 / `/screen` `/shot` 用的临时文件用完就删（删不掉的一天后清理）。
- 审计：`logs/audit-日期.log` 只追加、不清理，只记元数据（你发的命令或消息长度、点了哪个按钮、自动放行的工具摘要、对方电脑发来的是什么类型），不记消息内容。

## 命令

`/open` `/new` `/sync` `/fork` `/handoff` `/move` `/account` `/model` `/effort` `/mode` `/stop` `/get` `/diff` `/history` `/screen` `/shot` `/status` `/approvals` `/clear` `/panic` `/resume_hub` `/start`（帮助）

- `/clear`：在某个群的「圣旨」里发 = 清空这个群的话题和消息（用量面板保留，对话记忆不丢）；在上朝发 `/clear` = 总调度（`commandDefault`）那台电脑清空它所有的群和上朝，`/clear mac` = Mac 清空它自己的群。bot 只能删 48 小时内的消息；每个群记住上次清到哪里，下次只扫那之后的，连续 3 批一条都删不掉就停。
- `/panic`：紧急停止。私聊 bot、上朝或任何群里发都行（发得再晚也照样生效）；在上朝发 = 两台电脑各自都停。关掉这台电脑所有会话（Codex 连进程树一起），拒绝所有待批卡片，清空排队、额度重置后自动继续和重启后自动继续。之后一直暂停：不接新消息（`/status` 除外），不执行另一台电脑派来的任务、结果和安装包，桌面权限请求回电脑上处理，Hub 重启后仍然暂停并在上朝提醒。`/resume_hub` 恢复（同样在上朝发 = 两台都恢复）；被停掉的任务不会自动继续。

## 账号安全建议

- Telegram 账号 = 所有电脑的总钥匙：开两步验证（云密码 + 恢复邮箱）；手机 App 设密码锁；Telegram 电脑版设本地密码；设置 → 设备：清掉不认识的登录，「自动终止旧会话」设 1 周。
- 可选：每个群开「自动删除消息」（例如 1 周），否则 Telegram 会永久保存所有代码片段、diff、路径。
- 每台电脑装一个远程桌面（开 2FA、只允许自己的设备），Hub 自己挂了或要点 GUI 对话框时用。
- Windows：「Windows Time」服务设为自动（时钟偏了会让「过期消息」「对方在不在线」判断出错）。Mac：插电时不睡眠、系统更新只下载不安装、钥匙串关掉自动锁定（否则锁屏后 Hub 可能读不到 Claude 登录）。
